# 诗玛财务 AI 工作台

独立的财务工作台，当前包含淘宝、天猫及京东推广费查询。代码、启动入口、依赖和数据目录独立，不依赖原运营工作台运行。抖音账号可保存，查询尚未接入。

## 启动

当前Mac已准备本机开发运行依赖，可双击 `启动财务工作台.command`；也可在本目录执行 `npm start`。

在其他开发电脑上安装 Node.js，执行 `npm ci` 后 `npm start`。随目录提供的node_modules仅适用于当前macOS架构；换系统时按package-lock重新安装，不能直接使用Mac依赖启动Windows版。Windows源码入口为 `启动财务工作台.cmd`。

## 功能

- 多平台、多账号推广费查询；本月、近3个月、自定义日期，1—20个账号并行。
- 失败或暂停后仅补查失败项，已成功项保留；失败不记作零元。
- 查询记录按店铺导出CSV。
- 账号导入支持 Excel 表格（.xlsx/.xls/.csv）与 JSON 导出文件，包含平台、账号及明文密码。表格表头需含「平台」「账号」「密码」三列（列顺序不限，可另加「店铺名」列），平台列支持淘宝/淘天/天猫/京东/抖店等写法，空白平台沿用上一行；财务一店一账号，账号列只认单值列，客服排班表的早班/晚班双列结构不属于本软件，不参与识别；重复账号跳过，不覆盖已有账号，无法识别的行整行忽略并在结果里说明原因；本机仍加密保存密码。
- 登录验证、登录失败或页面异常时，恢复对应官方窗口、激活应用并置前取得焦点，短时置顶后释放。正常查询隐藏执行。京东失败授权子窗口保留供处理。

首次使用填写自己的账号，或使用原工作台“导出账号”后在这里导入。账号导出文件包含密码，请妥善保管；不自动复制原工作台的Cookie、登录状态、查询记录或真实账号。

数据位于系统应用数据目录下的 `shima-finance-ai-workbench`：macOS为 `~/Library/Application Support/shima-finance-ai-workbench`，Windows为 `%APPDATA%\shima-finance-ai-workbench`。每账号独立持久会话。

## 提前登录

账号信息下显示登录状态；操作列的登录、编辑、删除横向排列。账号行点击“登录”，可提前完成官方登录及人工验证，不读取推广费。点击“重新登录”会重新访问官方业务页核验当前会话；会话及账号身份仍有效时直接确认，不再提交账号密码，确需认证时才进入原登录流程。成功后刷新该账号独立持久会话到磁盘，查询仍核对官方登录及店铺/京东账户身份；失效时按原登录流程处理。界面以“已登录”及“上次确认”时间显示最近确认记录，按钮显示“重新登录”，该记录，不保证平台会话永不过期。登录串行，登录期间禁止查询、编辑、删除和导入导出；可取消等待。修改账号、密码或平台会更换会话并清除已保存登录标记。验证码及协议由用户在官方窗口处理；未知登录提交沿原检查点继续；淘宝、天猫和京东均预填空白账号密码框但不自动重复提交，不覆盖已有输入，验证码和协议由人工处理。

## 登录与一键查询流程

先在账号行点击“登录”，完成官方验证。随后勾选账号、选择日期并点击“获取推广费”，程序会核对身份并复用同一账号的持久会话；已登录账号在后台读取，只有需要登录、验证或出现异常时才展示对应窗口。提前登录或人工认证成功的账号主窗口在查询后隐藏保留，后续继续使用同一页面窗口和账号会话；关闭程序、删除账号或修改凭据时才释放。重新启动恢复的是持久会话，平台仍可能要求重新认证。

提前登录和查询共用身份核验、会话落盘和确认时间更新。“已登录”表示最近一次核验成功；明确需要认证后改为“需确认登录”，保留上次确认时间。页面尚未加载出身份不会直接判为登录过期。京东已确认账号优先打开京准通复用会话，再按需回到京麦认证。

取消登录或暂停查询会停止后续操作；“仅补查失败 / 暂停店铺”沿用原日期，保留成功项。未知登录提交记录不自动清除或重复提交，需在官方窗口确认。不同账号及其他工作台之间不复制登录凭据或Cookie。

自动提交使用统一的输入校验间隔：填写账号后等待约0.5秒，填写密码后等待约1秒，再次核对输入值、验证码和协议状态后才点击。等待期间可取消；用户修改输入后交由人工处理。这用于等待页面处理输入，不保证平台免验证。

### 状态和恢复边界

| 当前情况 | 程序行为 |
| --- | --- |
| 提前登录成功 | 身份匹配、会话落盘、本地确认写入均成功后，才确认登录并清除本账号提交检查点；不生成费用记录 |
| 查询时会话有效 | 同账号持久分区内后台核验、读取所选期间费用 |
| 淘宝/天猫账单中途需要登录或验证 | 保留当前官方窗口，等待人工处理，随后至多恢复一次原日期账单；不覆盖认证页去千牛首页反复登录 |
| 恢复后再要求认证 | 结束本项并保存原因，其他账号继续；不循环重复认证 |
| 页面只有未知或加载中状态 | 不据此确认登录或清除检查点；推广业务首页只可作为返回原账单的导航依据 |
| 身份或日期不符 | 不写金额、不清未知提交检查点，保留失败原因 |
| 京东授权子窗口 | 单独核对目标推广账户，不能清理主账号提交检查点；失败子窗口保留 |
| 取消发生在导航或脚本等待中 | 中止等待并停止后续操作，迟到结果不写成功；后台或暂停时不抢焦点 |

本轮先核对功能关联，再完成两轮方案优化：第一轮集中登录确认的提交时机，第二轮明确账单域认证恢复次数、父子账户边界和取消行为，随后按定稿修改。原有账号独立会话、查询金额校验、成功项保留和持久写入失败停止派发规则继续有效。

## 检查与构建

`npm run check`：校验来源哈希并执行相关业务回归。

`npm run test:ui`：独立隐藏Electron进程，使用合成账号及合成查询适配器，验证实际表单、IPC、系统加密、账号JSON/费用CSV、跨进程恢复，以及本地拦截HTTPS合成网页的“查询→认证控件→原日期账单恢复”流程；不访问真实平台，不动正式数据。设置 `SHIMA_FINANCE_EVIDENCE` 可指定报告目录。

`npm run package:win`：通过固定electron-builder 26.15.3生成Windows x64免安装版。`npm run package:mac`：生成Mac应用目录。构建需要下载对应依赖和运行时；源码拆分不等于已生成或验证Windows成品。

Electron固定43.8.3，使用独立安装的本机验收运行时；没有npm生产依赖、Python、原工作台授权或云端AI密钥依赖。“财务 AI 工作台”是独立产品名称，本轮未增加AI分析或预测功能。Excel解析使用本地随附的SheetJS单文件 `vendor/xlsx.full.min.js`（SheetJS 0.20.3，CDN官方分发，无npm生产依赖），来源与SHA256见 `source-files.json`。本机打包输出目录按版本递增（当前为 `release120`；`release` 目录被系统残留占用时无法清空）。

来源文件及SHA256见 `source-files.json`。只保留推广费、官方登录识别及必要界面，不附带真实用户数据。

图标在1024像素透明画布中将原图等比例缩为860像素并居中，四边增加82像素透明留白，用于统一Dock视觉大小；美元、AI和配色保持原设计。

## 页面操作稳定性

京东日期筛选逐步确认弹层展开、月份变化、日期选中及最终提交；日期输入、日期格、翻月、确认及外部关闭操作统一先悬停，再重新定位和命中检查，位置连续一致后才按下；不会沿用悬停前的坐标。重复可见日期输入或弹层会明确拒绝，避免操作和验证混用；确认按钮只从当前日期弹层内唯一定位，不使用其他弹窗的同名按钮。点击未生效时先关闭并重置日期面板（不响应Esc时原生点击面板外的可见静态账单标题；遮挡或交互标题不会点击，必须确认弹层已关闭），整组最多重试一次；不重放登录、授权或凭据提交。日期、账户和本轮现金账单响应仍须一致才返回金额。

千牛仅在无副作用的页面读取遭遇导航上下文切换时有限重试；控件显示旧范围时在20秒页面就绪期限内等待目标状态，不再在约700毫秒后提前判错；加载状态会清除之前的金额稳定计数。财务导航只操作唯一可见且未遮挡的菜单控件，点击一次后等待下一菜单或账单区域真正就绪；静态同名文字不作为入口，点击失效不会反复切换菜单。

身份、扣款、交易日期和实际范围仍须匹配，动态提示和时钟不参与金额稳定判定。异常保留原因供补查。

`npm run check` 包含隔离 Electron 实际日历控件验收：1280/620 窗口、500ms延迟选中、丢失首击、450ms慢翻月、同日起止及需确认按钮、半选范围重入、独立窗口并行和等待中取消；不访问真实平台或正式账号。此验收不能代替线上平台或Windows实测。

登录操作使用 Electron 原生鼠标事件点击账号、密码框和登录按钮，逐字符发送键盘事件输入；不通过页面脚本赋值完成正式登录。页面脚本仅定位和检查控件。控件遮挡、位置变化、已有输入或无法确认的嵌入框会停止操作交由人工；未知提交仅预填，不重复提交。

## 京东授权状态

授权列表按归一化表头读取账户、有效期和状态，等待表格/分页真实就绪，不再依赖整页出现连续“授权状态”文字或固定列序号。只打开“生效中”的授权记录；同账户多条记录或跨页重复只查询一次，过期记录不会遮盖同账户的有效授权。

查询记录上方的“京东授权提醒”列出已过期记录的账户名称、ID、原有效期和检查时间。同账户仍有有效授权时明确提示“旧授权已过期，当前仍有生效授权”，继续查询。只有过期授权时显示原因和金额“—”，不记为0。授权提示独立保存，不增加费用项目或待补查数量。补查仍保留已成功项目和原目标范围，不自动混入新授权账户。
